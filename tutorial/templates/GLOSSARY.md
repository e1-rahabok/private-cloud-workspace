# Glossary

Every ID prefix and term the project uses, one meaning each. Written together: the person gives the terms that come from the field or carry identity; the agent keeps the list complete and checks that no two terms overlap.

## IDs

| ID | Meaning | Defined in |
|---|---|---|
| GOAL-n | A goal: an outcome with its measure | BRIEF.md |
| SCOPE-n | A line of scope, in or out, with its reason | BRIEF.md |
| PRINCIPLE-n | A rule that settles a trade-off | BRIEF.md |
| CONSTRAINT-n | A limit the design must accept | BRIEF.md |
| ASSUMPTION-n | A statement believed true and not yet verified | BRIEF.md |
| RISK-n | An uncertain event that would hurt a goal | BRIEF.md |
| DEPENDENCY-n | Something the work needs from outside it | BRIEF.md |
| R-AREA-nnn | A requirement | Requirement files |
| T-AREA-nnnx | A test scenario of a requirement | Requirement files |
| DESIGN-n | A design choice, with its reasons and rejected options | DESIGN.md |
| C<n> | A contract between two parts | DESIGN.md |
| Q-n | A question asking the person for input | OPEN-QUESTIONS.md |
| M<n> | A milestone, numbered in the order of work | ROADMAP.md |
