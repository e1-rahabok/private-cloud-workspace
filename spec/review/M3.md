# M3 review: Agent E2 serves PCM and isvara.io

Not ready: some of this milestone's work is still open.

## Purpose and reason

PCM and isvara.io both ask Agent E2 questions, and an answer can take minutes. M3 builds the one Agent E2 service that both call. A question starts a job that shows its stage, so the person sees that Agent E2 is still working and has not stopped. A question can carry a VMware screenshot or a CSV file, and a conversation continues over several turns. Every answer lists the knowledge files it used, with title and number, so a reader can open the source, and it reports its time and use. A missing fact is said, never guessed, and a question about installation or design points to Broadcom's documentation. The model is Gemma 4 31B through Vercel AI Gateway. The service only wraps the answering that exists: no knowledge file and no model setting changes.

## Changes for users and for you

For customers and visitors, nothing yet: PCM and isvara.io keep working as they do today and move to the new calls in later milestones. For you, nothing changes in what Agent E2 knows or how it answers. The band of a value in a question stays off until M5.

### The goals, scope, limits and assumptions behind them

- **Constraint: Spending on Vercel AI Gateway.** A test run that calls a model has a budget of US$100, counted on the money it spends. The full benchmark round never runs: Agent E2 is checked by its answer set of about 15 questions and the free automatic checks. A run of the answer set starts only when the author says go. An answer or a grade whose inputs have not changed is reused and not paid for again. After go-live, isvara.io stays within US$50 a month on the gateway alone; the Vercel subscription of US$40 is apart. The author tracks spending on vercel.com and raises a budget when needed. Reason: the author pays for the product himself; three full rounds in one week of November 2026 spent US$350, most of it on answers that had not changed; a full round takes about 3 hours and costs too much, and Agent E2's knowledge has barely changed since the last one.
- **Scope: A lab demo with a cloud model.** PCM runs in the author's lab; Agent E2 uses a cloud model through Vercel AI Gateway; isvara.io is public on Vercel. Reason: a plan that describes two futures at once leads each session to build toward the wrong one.
- **Scope: Agent E2 in release 1.0.** Reason: accuracy matters more than time; even minutes are better than waiting for a person. Accuracy comes before speed. An answer may take minutes, with no streaming, and the user always sees that Agent E2 is still working. Free-text answers are graded automatically by Claude Haiku 5.5 at low effort as judge: the cheapest grader, from another maker than the answering model, and the author's 20-answer check guards it; Opus 5.5 replaces it if it fails (the author, 2026-11-28: no bill beyond the existing gateway spend). The answer set holds about 15 free-text questions in release 1.0 and grows toward 40 after it. Reason: isvara.io's quiz is multiple choice and never uses the grader. The model is Gemma 4 31B, or a later version when one comes. Every knowledge file is used, drafts included; a review gate on files waits until after go-live, because the author has no time to review each file.
- **Principle: Accurate before complete.** A confident wrong answer is worse than none; Agent E2 fails if it gives one, and "I don't know" is acceptable, as it is from an expert. Reason: an administrator acts on the answer in production.
- **Scope: isvara.io rebuilt.** Same look and feel, new functionality; the old site goes. Reason: nothing brings people back to isvara.io today, and they cannot tell what has changed. Its pages are AI rewrites of Agent E2's knowledge files, with no AI-speak. A cited source opens the knowledge file, with a note that it is written for a model. The injection guard sits in isvara.io, before it calls Agent E2. The "load-and-ask" design retires. Downloads and the weekly refresh of the Word books continue, as downloads. It is built in the fork e1-rahabok/isvara, served as a parallel site, and switched over in one release once the author has compared it with isvara.io; each feature waits for the author's review of the before and after.
- **Constraint: No data on a cluster's environment.** In release 1.0, neither the VCF vCommunity Adapter nor Agent E2 knows whether a cluster is production or non-production, and no caller sends it. Reason: no data source holds it in the lab.
- **Scope: PCM's live demo.** Reason: one workspace on live data proves the connection with the least work. The L2 workspace only, for performance and capacity management only. The inventory comes from VCF Operations and starts at the VCF instance; an object's ID is its VCF Operations resource ID. Class of service, region, environment and time zone exist only in the synthetic demo. PCM shows what the VCF vCommunity Adapter publishes and says "No data" when a value is stale. PCM stores no metrics. It keeps each Agent E2 answer with its trace ID and rating for the 30 days that Agent E2 keeps the trace. PCM may compute for display and never writes to VCF Operations. Lab facts may go to the cloud model. Actions, stories, cases and the calendar are out of release 1.0.
- **Scope: Day 2 knowledge only.** The knowledge covers running, monitoring, troubleshooting and planning. Design, installation, building, configuration and upgrades (Day 0 and Day 1) are out, and Agent E2 says so when asked and points to Broadcom's documentation. Reason: Day 1 knowledge changes with each release, and release 1.0 must be small enough to finish.
- **Goal: Release 1.0 success.** VMware colleagues and customers who see the PCM demo find it useful and want to copy the repositories privately, to customise and deploy in their own private cloud; Agent E2 explains a real lab KPI correctly in the live demo; on isvara.io every knowledge file is a page people can read and bookmark, Agent E2 answers with sources, and the exam exists; every contract between the repositories is checked automatically. Reason: the author demos PCM to these people, and their wish to copy it is the first sign of “Value without the author”; isvara.io's pages today are deep, hard to navigate and hard to place in the whole.

## Risks

- **Agent E2 gives confident wrong answers.** Effect: Agent E2 fails by “Accurate before complete”. An earlier generation was confidently wrong on 31 to 41% of open answers. Reduced by: the graded answer set on every change of model or prompt, sources on every answer, the Day 2 scope.
- **Gateway spending exceeds the budget.** Effect: the author pays more than “Spending on Vercel AI Gateway”. Reduced by: a daily ceiling on model calls, limits per visitor; a test run that stops at its budget, unchanged answers and grades reused, and the full round only before a milestone is closed.
- **One vendor for hosting and the model gateway.** Effect: a change of price, model or terms at Vercel stops isvara.io or Agent E2. Reduced by: the gateway is OpenAI-compatible and the model is a setting; the on-premises deployment uses a local model server.
