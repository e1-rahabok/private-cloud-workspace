### The goals, scope, limits and assumptions behind them

- **Scope: isvara.io rebuilt.** Same look and feel, new functionality; the old site goes. Reason: nothing brings people back to isvara.io today, and they cannot tell what has changed. Its pages are AI rewrites of Agent E2's knowledge files, with no AI-speak. A cited source opens the knowledge file, with a note that it is written for a model. The injection guard sits in isvara.io, before it calls Agent E2. The "load-and-ask" design retires. Downloads and the weekly refresh of the Word books continue, as downloads. It is built in the fork e1-rahabok/isvara, served as a parallel site, and switched over in one release once the author has compared it with isvara.io; each feature waits for the author's review of the before and after.
- **Scope: Agent E2 in release 1.0.** Reason: accuracy matters more than time; even minutes are better than waiting for a person. Accuracy comes before speed. An answer may take minutes, with no streaming, and the user always sees that Agent E2 is still working. Free-text answers are graded automatically by Claude Haiku 5.5 at low effort as judge: the cheapest grader, from another maker than the answering model, and the author's 20-answer check guards it; Opus 5.5 replaces it if it fails (the author, 2026-11-28: no bill beyond the existing gateway spend). The answer set holds about 15 free-text questions in release 1.0 and grows toward 40 after it. Reason: isvara.io's quiz is multiple choice and never uses the grader. The model is Gemma 4 31B, or a later version when one comes. Every knowledge file is used, drafts included; a review gate on files waits until after go-live, because the author has no time to review each file.
- **Principle: Accurate before complete.** A confident wrong answer is worse than none; Agent E2 fails if it gives one, and "I don't know" is acceptable, as it is from an expert. Reason: an administrator acts on the answer in production.
- **Scope: Day 2 knowledge only.** The knowledge covers running, monitoring, troubleshooting and planning. Design, installation, building, configuration and upgrades (Day 0 and Day 1) are out, and Agent E2 says so when asked and points to Broadcom's documentation. Reason: Day 1 knowledge changes with each release, and release 1.0 must be small enough to finish.
- **Constraint: Spending on Vercel AI Gateway.** A test run that calls a model has a budget of US$100, counted on the money it spends; the budget caps a run and approves none. The full benchmark round never runs: Agent E2 is checked by its answer set of about 15 questions and the free automatic checks. A run that spends the author's money, a run of the answer set included, starts only when the author says go, after Claude has told the author its cost, its time and what it proves; whether small runs may start without asking is still open. An answer or a grade whose inputs have not changed is reused and not paid for again. After go-live, isvara.io stays within US$50 a month on the gateway alone; the Vercel subscription of US$40 is apart. The author tracks spending on vercel.com and raises a budget when needed. Reason: the author pays for the product himself; three full rounds in one week of November 2026 spent US$350, most of it on answers that had not changed; a full round takes about 3 hours and costs too much, and Agent E2's knowledge has barely changed since the last one; on 2026-11-28 a full round entered the plan before every milestone close, and the author learnt its price, US$71, only after the plan was merged.
- **Scope: isvara.io's features in release 1.0.** The three learning paths as navigation; articles rewritten from knowledge files; infographics; Ask Agent E2; contributions; a quiz with a mastery map, the exam and the 2am game; calculators on Agent E2's catalog; a weekly summary of changes. Dropped: the podcast, the Operations Score, the cost calculator and SLA builder, the self-assessment and a global leaderboard. Reason: an administrator comes back weekly for tools, an expert to ask and learning; the dropped features serve none of these or hold knowledge of their own.
- **Principle: The customer's data stays with the customer.** In the on-premises deployment nothing leaves the customer's network. On isvara.io, visitors remove their own IP addresses and host names before uploading, and the site keeps data only as “Data the system keeps, and for how long” says. Reason: customers will not share data that can leak.
- **Constraint: The author's review time.** The author cannot review each knowledge file or each pull request one by one. Reason: one person, with other work.

### Contributions on isvara.io

- **[The visitor agrees before sending.](https://github.com/e1-rahabok/isvara/blob/main/spec/requirements/contributions.md#r-contrib-002-the-visitor-agrees-before-sending)** Isvara.io may use a contribution only if the sender may share it and it holds no customer data.

- **[No address is kept, and files go within 30 days.](https://github.com/e1-rahabok/isvara/blob/main/spec/requirements/contributions.md#r-contrib-004-no-address-is-kept-and-files-go-within-30-days)** Data that is not kept cannot leak.
- **[The limits are settings.](https://github.com/e1-rahabok/isvara/blob/main/spec/requirements/contributions.md#r-contrib-006-the-limits-are-settings)** Limits change as use grows, and a setting changes without a redeploy.

### Protection of isvara.io

- **[Files are checked by their content.](https://github.com/e1-rahabok/isvara/blob/main/spec/requirements/protection.md#r-protect-004-files-are-checked-by-their-content)** A file named.png can hold anything, and image metadata can carry a customer's location or host names.
- **[Ask and Contribute can be closed at once.](https://github.com/e1-rahabok/isvara/blob/main/spec/requirements/protection.md#r-protect-006-ask-and-contribute-can-be-closed-at-once)** When an attack or a bug starts spending, it must stop at once, before a redeploy finishes.
- **[Admin pages ask for a password, never a key in the address.](https://github.com/e1-rahabok/isvara/blob/main/spec/requirements/protection.md#r-protect-007-admin-pages-ask-for-a-password-never-a-key-in-the-address)** A key in the address is kept in browser history, proxy logs and Vercel's request logs, and a plain string comparison leaks the key's length and prefix through its timing (OWASP ASVS V2, authentication, and V3, session management; OWASP Top 10 A01, broken access control, and A07, identification and authentication failures).
- **[Links in an answer go only to known sites.](https://github.com/e1-rahabok/isvara/blob/main/spec/requirements/protection.md#r-protect-008-links-in-an-answer-go-only-to-known-sites)** An answer can carry a link that an injected instruction placed there, and a link to an unknown site can leak the question in its address or lead to a phishing page (OWASP Top 10 for LLM applications, LLM05, improper output handling).
